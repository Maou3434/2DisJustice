# Portfolio Development & Design Rules

## 1. Anti-Vibe-Coded Standard
- Never output generic "AI SaaS" templates: no purple/indigo gradient text, no blurred decorative glowing blobs, no cards-inside-cards-inside-cards, no Lucide icon boxes next to every line.
- Never write filler copy ("passionate developer", "supercharge your workflow", "seamless experience"). Use concrete engineering specifics, architecture diagrams, and demonstrable artifacts.
- No fake evidence: never fabricate client logos, ratings, metrics, or testimonials.

## 2. Dimensional & 3D Integration
- The portfolio must possess real visual depth: foreground, midground, and background relationships, camera-aware scroll choreography, and tangible 3D/WebGL elements.
- Performance is a non-negotiable requirement: optimize draw calls, lazy-load 3D scenes, minimize polygon counts, respect `prefers-reduced-motion`, and provide fluid mobile fallbacks.

## 3. Two Distinct Variations
- **Variation A (AI Free Style)**: Striking architectural/experimental editorial direction with bold spatial layout and distinct typographic personality.
- **Variation B (Ghost of Tsushima-Inspired)**: Atmospheric Japanese/samurai art direction (sumi ink, washi paper, wet stone, weathered steel, cinnabar accents, environmental wind/fog, calligraphic tension and negative space). Not a fan page or replica of game UI; a professional personal portfolio with cinematic feudal Japanese art direction.

## 4. Software Engineering & Git Discipline
- Adhere strictly to the SDLC sequence: Reconnaissance → Requirements → Research & Grilling → Architecture → Design Tokens & System → Staged Implementation → Rigorous Review.
- Make small, descriptive, atomic Git commits with clear prefixes (`feat:`, `chore:`, `docs:`, `perf:`).
